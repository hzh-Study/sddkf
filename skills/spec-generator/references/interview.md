# 采访流程

## 原则

- **逐轮进行**：每轮把当前能问的问题一次问完，不要挤牙膏式单问。
- **每题附推荐答案**：推荐答案必须具体、可直接采用；用户回答「是」即采用推荐答案。
- **能推导的不问**：能从用户描述或上一轮回答安全推导的，直接给出推导值并请用户确认。
- **不中断主线**：用户不回答某题时，采用推荐答案并在最终回报中列出该假设。
- **落库**：把每个回答映射到 `references/assembly.md` 中的占位符键，后续装配直接使用。

## 第 1 轮：项目轮廓

| 问题 | 推荐答案示例 |
| --- | --- |
| 项目叫什么名字？ | 从描述推导，例如「Vue3 博客」 |
| 用一句话说明项目做什么？ | 从描述提炼，例如「一个支持文章发布与评论的博客站点」 |
| 技术栈与主要版本？ | 从第一句话提取，例如「Vue 3 + Vite + TypeScript」 |
| 部署到哪里？ | 「静态托管（如 Vercel / Netlify）」或按栈推荐 |

## 第 2 轮：工程配置

| 问题 | 推荐答案示例 |
| --- | --- |
| 构建工具用什么？ | 按栈推荐，例如 Vue3 用 Vite、Spring Boot 用 Maven |
| 包管理器用什么？ | 按栈推荐，例如 Vue3 用 npm、Python 用 uv |
| 需要数据库吗？用什么？ | 「不需要」或按项目推荐，例如 SQLite |
| 需要登录鉴权吗？ | 「不需要登录」；需要时推荐具体方案 |
| 注释和文档用什么语言？ | 「中文」 |

## 第 3 轮：质量与验证

| 问题 | 推荐答案示例 |
| --- | --- |
| 测试框架用什么？ | 按栈推荐，例如 Vue3 用 Vitest、Python 用 pytest |
| 测试命令是什么？ | 例如 `npm test`、`pytest` |
| 构建/检查命令是什么？ | 例如 `npm run build`、`python manage.py check` |
| 静态检查命令是什么？ | 例如 `npm run lint`、`ruff check .` |
| 代码主要放在哪些目录？ | 按栈惯例列出现有或计划目录 |
| 核心依赖有哪些？ | 只列已确认的依赖，不臆造 |

## 第 4 轮：业务术语

1. 从第 1 轮的「一句话简介」和后续回答中提炼 3–6 个业务术语。
2. 每个术语给出定义，例如「文章：博客的核心内容单元」。
3. 一次性列出并问：「这些术语和定义准确吗？需要补充或修改吗？」
4. 用户确认后写入 `GLOSSARY.md`。

## 结束后

- 汇总全部答案，检查是否有缺失的占位符；缺失就回到对应轮次追问。
- 按 `references/assembly.md` 装配，写入目标项目根目录。
